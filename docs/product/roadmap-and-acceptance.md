# Roadmap And Acceptance

One coherent first-release implementation spans internal checks 1A financial/import, 1B private durable workspace, and 1C connected agent research. These are dependency checks, not separate deliveries or user milestone approvals. External rights/access/budget/resource authority remain separate activation gates.

## Acceptance Matrix

| Slice | Required check | Evidence boundary |
| --- | --- | --- |
| 1A | Independent FIFO/FX/fees/dividends/split arithmetic; repeat/overlap/stale-confirm; unknown metrics | Synthetic/sample tests do not establish Revolut compatibility or actual account reconciliation |
| 1B | Actual SQL transactions/claims/fencing/cancel/attempt limits; private artifact/auth routes; durable restart; daily/DST | LocalDB/HTTP tests do not establish deployed Entra, Azure SQL roles, cold starts or backup recovery |
| 1C | Same real dispatcher/handlers with external fixture transports; held, sector, outside, two horizons, critique/follow-up/gates, trace | FixtureReplay is not a real model, ModelOnFixtures is not live markets, and neither proves investment quality |
| Delivery | Complete solution test/build; secure templates/images/CI; browser workflow; operating/manual docs | Missing essential source or end-to-end checks keep overall readiness Partial/Blocked |
| Activation | Verified real baseline/candidates, source rights, exact model capabilities/rates/geography, auth/schema/MI, forecast and authority | No resource purchase, deployment, login or model call has been performed by this infrastructure effort |

Prior main-owner test evidence supplied for this task: **9** financial/pipeline, **75** infrastructure including actual SQL LocalDB and recorded model/source HTTP, and **60** web/schedule/host tests. These are reported prior results, not rerun counts or a permanent total; the main owner may add tests. Local durable restart/browser verification is pending that owner's testing.

Required final scenario: an isolated confirmed portfolio, at least one held instrument plus a reviewed outside candidate and relevant sector, distinct long-term/tactical findings/counterarguments, an independent critic, bounded follow-up, deterministic policy gates, a qualified A-I brief and inspectable persisted task/tool/evidence/usage history. Change evidence/critic input to prove meaningful loop branching. Exercise disabled/missing/refused/malformed/denied/budget/cancel/recovery paths, not just success.

Do not label the first release production-ready while source binding, actual-format reconciliation, safe maintenance/restore or live identity/model/source acceptance remains unresolved. Numerical policy alone does not prevent useful research, but missing scenario inputs prevent suitability/sizing.
