# Daily Brief And Schedule

The [InvestmentBrief contract](../../src/Pii.Application/Contracts.cs) carries run/revision/as-of/mode/AI status, deterministic facts, sections, assessments/gates, limitations and optional previousRunId. It is a stored private advisory report, not a broker action or notification service.

Required section intent: A executive summary/no-action; B EUR portfolio/quality; C portfolio health/exposure/thesis; D prioritized assessments and manual verification; E relevant sector/outside opportunities; F market developments; G upcoming events and confidence/availability; H prior-report changes; I missing/stale/uncertain data and policy status. Actual absent sections/fields must be labeled unavailable, not fabricated. Current real event/ETF/cash/snapshot/performance coverage is limited; source/critic/gate evidence must substantiate summaries.

LongTerm and Tactical findings/counterarguments remain separate for held and outside candidates. Unconfigured numerical policy prohibits asserting sized or compliant action; HOLD needs supported thesis, REVIEW/WATCHLIST/no-action remain valid. FixtureReplay/ModelOnFixtures/Live and AI status must stay distinct from overall run status; exit0/completed invocation does not establish successful AI. Deterministic fallback is useful degraded operation, not the entire research product.

Production job runs every minute UTC `* * * * *` with `--daily`, not the superseded plan's double-UTC daily candidate trigger. [DailySchedule](../../src/Pii.Worker/DailySchedule.cs) converts actual time to Europe/Vilnius and is due when local hour>=08, key `daily:vilnius:yyyy-MM-dd:v<ScheduleVersion>`. Same local-date key deduplicates repeats across late starts/DST/weekends. Before08 daily submission skips but pending SQL work still executes; empty/no confirmed portfolio never seeds holdings.

This is a due-time **generation intent**, not an exact08 publication SLA. Normal work waits for cadence, startup/image pull/SQL resume/bounded processing; all remain live-unmeasured. A worker may overlap another execution; SQL fencing prevents stale publication. Existing pending/expired backlog is consumed/stopped under deadlines and generation limits. A full missed prior day is not backdated with later evidence: current date gets its own actual cutoff/time, missing history remains a gap. No retroactive older daily key creation is claimed by DueKey.

Weekend generation stays enabled. Do not claim weekly return without appropriate valuations/flows, last-close freshness without calendar evidence, broad news without licensed coverage, or automatic weekend inference/cache optimization without actual code. First report says no previous report; later comparisons require pinned prior context, not rewriting history. Notifications/email/push and calibrated outcomes are later work.
